# UniPi Oino 1.0.13

This update brings together the changes from 1.0.6 through 1.0.13 for everyone upgrading from the public 1.0.5 release.

## Faster, steadier chats

- Large conversations open, scroll and send with less work spent rereading their history. A busy chat is less likely to make the whole host appear unresponsive.
- Idle project services can go to sleep to free memory and wake when needed. Opening chats across many projects no longer runs into the service limit and locks you out of new chats.
- Reconnecting, reopening a conversation and sending follow-ups are more reliable. Delivered messages no longer leave an extra “Sending…” copy behind.
- Follow-ups remain visible as queued while work or a permission request is pending. Routine board housekeeping no longer asks for permission after every turn. Agent shell commands still follow your autonomy setting.
- Switching models after a project has gone idle works in one click, including when leaving or changing a Fusion pair. Answered question cards stay answered after changing chats or restarting.

## MCP connections belong to the right project

- Add and manage MCP servers in Settings or with `/mcp`, choosing Global or the current project. You can use the form or paste JSON.
- Project connections load for that project's chats, instead of depending on the folder where the host started. Project settings can override a global server without affecting other projects.
- Existing project configuration files are supported, including `.oino/mcp.json`, `.pi/mcp.json`, `.unipi/config/mcp/mcp-config.json` and `.mcp.json`.
- A trust prompt keeps a newly opened folder's MCP settings off until you approve them. Secret headers entered through Settings are stored separately, leaving a placeholder in the project file.
- Command-based servers explain when they need High autonomy and when to reconnect. Hand-edited configuration can be reloaded without restarting the app.

## Easier projects and boards

- The project picker combines folder browsing, typed paths, keyboard navigation and frequent projects powered by zoxide when available. Your home folder requires an explicit choice.
- Board tools and commands are offered only in projects with an active board. Set one up from Superagent when you need it; archived boards stop offering task-creation tools.
- Board images and tall screenshots fit their attachment tiles. Filenames, sizes and removable pasted-image chips make attachments easier to check.
- Review replies upload their attachments when submitted, so discarding an unsent review note does not upload its files.
- Phone-layout sorting, pinning and attachment controls are easier to use. Long work-only timeline sections collapse together, and inline code has a copy action.
- Reopening a chat no longer incorrectly makes it read-only. Refused graph or swarm requests keep your prompt and images without creating an empty chat.

## Installing and updating

Use the assets attached to this release and check `SHA256SUMS`. Linux AppImage, Windows and macOS updater bundles use signed updates. Debian packages use the Download action and your package manager. Android verifies the download checksum and requires the existing release signing certificate. Keep your phone app and desktop/host on matching versions.

macOS builds are ad-hoc signed, not Apple-notarized, and may need right-click → Open on first launch. Desktop updater signatures are separate from operating-system code signing.

## Known limitations

- Running `/kanboard status` while a permission card is open can hide the answer inside the collapsed “Worked for …” section. Answer the permission card, then expand that section to read it.
- Applying or leaving a Fusion pair can reset the thinking level. Check it after switching. A newly created board can leave the open chat's skill count stale even though its board tools work.
- An unknown slash command can remain as an unsent draft without an explanation. Clear it before typing another message.
- Physical Android acceptance and a real-account Linear connection were not rerun in the final release-candidate QA. Phone-layout and MCP checks used isolated test profiles and offline servers. Some heavy-load performance budgets remain open.
