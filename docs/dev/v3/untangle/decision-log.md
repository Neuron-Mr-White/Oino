## C. Implementation plan — five disjoint slices

All paths are repository-relative. Work from the current tree, confirm each exact path is absent from `dirty-by-others.txt` **and** has not become dirty since this plan, and stop/reassign if not. New files must also be checked for untracked work. No worker may expand a slice's file set without re-planning disjoint ownership. Run gates from the indicated workspace; report baseline failures separately. No generated `extensions/dist` outputs. Commit each slice separately only under the implementing owner's instructions; this decision step makes no commits.

1. **Prompt inputs — 1 file:** `crates/oino-resources/src/system_prompt.rs`. In private `insert_default_sections`, remove `options`, `declared` and the discard statement; update its sole call in `build_system_prompt_sections`. Remove local `declared` only after confirming it has no other use. Preserve all public options and emitted bytes. Gate: from root `cargo test -p oino-resources`. Risk low; no inventoried special-case finding removed.
2. **Cron transport ownership — 3 files:** `extensions/unipi/cron/src/lib.rs`, `extensions/unipi/cron/src/args.rs`, `extensions/unipi/cron/src/tools.rs`. Move the identical `Cron::host_op` body to a private module-level async `host_op` in `lib.rs`; have args and tools call that function with unchanged service availability check, payload, error mapping and call order. Move `list_value` to a module-level private function and update `args.rs` callers, retaining exact JSON. Remove only imports made unused. Gate: from `extensions`, `cargo test -p unipi-cron`. Risk low-to-medium: native tests cannot by themselves prove a live host call; verify both existing bodies are still identical before merging, otherwise stop. No counted special case removed.
3. **Status clock forwarding — 1 file:** `apps/unipi/src/components/status/LhSection.tsx`. Replace the local `useClock` forwarding body with direct `useClock` import from `../../lib/clock`; preserve the existing exported name via a re-export, so external imports remain valid. Preserve hook invocation order. Gate: from `apps/unipi`, `npx tsc --noEmit` and `npx vitest run src/lib/status/lh.test.ts`. Risk low; no counted special case removed. Repo textual search found no `useClock` import from `LhSection`, but the re-export avoids treating that as proof of no external consumers.
4. **Comments — 2 files:** `crates/oino-rpc/src/server.rs` and `apps/unipi/src/components/model/target.ts`. Remove only the confirmed restatements `/// Reply queue depth.` above `REPLY_QUEUE` and `/** Closes it. */` above `closeModelPicker`. Preserve all other contract, safety, external-reason and compatibility comments. Gate: root `cargo test -p oino-rpc`; from `apps/unipi`, `npx tsc --noEmit` and `npx vitest run src/components/model`. Risk negligible; no counted special case removed.
5. **Tests — 2 files, last:** `apps/unipi/protocol/fixtures/cron.json` and `crates/oino-tools/src/mutation_queue.rs`. (a) Extend the existing shared cron fixtures with independently authored valid and invalid `Control` requests for ASCII job-ID boundary lengths 64 and 65 and a valid `CronJob` with representative optional fields, checking the present Rust and TS validators first; keep any known divergence as a ticket rather than changing behavior. Existing `apps/unipi/crates/unipi-proto/tests/cron_fixtures.rs` and `apps/unipi/packages/protocol/tests/cron.test.ts` already consume that same file; do not edit them. (b) Rewrite `same_file_runs_in_order` to use oneshot channels: first operation signals it has entered and waits for release; after that signal, poll/register the second queued operation, verify it has not executed while the first is blocked, release the first, then assert `[1, 2]`. Use a bounded timeout only as a failure guard, not as an ordering mechanism; do not rely on `pending()` alone to prove the second registered, since it counts keys not waiters. If deterministic second-registration cannot be observed without a production seam, stop and ticket rather than add an unplanned file or weaken the test. Gate: root `cargo test -p oino-tools`; from `apps/unipi`, `cargo test -p unipi-proto`, `npx tsc --noEmit`, `npx vitest run packages/protocol/tests/cron.test.ts`. Risk: fixture validators may have intentional differences; no contract behavior may be changed to pass. Removes one inventoried test-only timing special case **only if** the deterministic handshake is completed and verified. Contract fixtures pin a subset; they do not eliminate the underlying copies.
