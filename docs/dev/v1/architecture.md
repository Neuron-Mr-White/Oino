# Architecture

Status: binding. See [README](README.md) for decisions (D-numbers) and ownership.

## 1. Workspaces and top-level layout

```text
Cargo.toml                 # root workspace: members = ["crates/*", "xtask"], resolver 3
rust-toolchain.toml        # channel 1.99.0, targets [wasm32-wasip2], components [rustfmt, clippy]
clippy.toml  rustfmt.toml  deny.toml
wit/
  oino-extension/          # package oino:extension@1.0.0 (one file per interface + worlds.wit)
  deps/                    # wasi 0.2.x (clocks, random, filesystem, io, cli) — no wasi:http
crates/                    # host libraries + clients + the `oino` binary
extensions/                # separate workspace, target wasm32-wasip2
  Cargo.toml               # members = ["sdk/*", "providers/*", "unipi/*", "fixtures/*"]
  sdk/{oino-extension, oino-extension-macros, oino-provider-kit, unipi-kit}/
  providers/{openai-compat, openai-responses, anthropic, router}/
  unipi/<package>/         # one dir per ported unipi package (unipi-port.md)
  fixtures/{echo, provider-faux, ui-probe, async-probe}/
  dist/                    # generated by `cargo xtask wasm` (not committed except checksums.json)
apps/                      # separate workspace (GPUI); path-depends on crates/*
  Cargo.toml  Cargo.lock
  oino-ui/  oino-desktop/  oino-mobile/  vendor/gpui-mobile/
xtask/                     # build/bundle/check tasks (replaces scripts/build-wasm-extensions.sh)
scripts/                   # installers, pi-oracle (fixture generators)
tests/e2e/                 # cross-crate golden tests driving the `oino` binary
docs/                      # user docs; docs/dev/v1 = specs
legacy/                    # frozen pre-v1 code (excluded from all workspaces; deleted in P5)
```

The root workspace never depends on GPUI, wasmtime-free crates never depend on wasmtime,
and no crate in `crates/` depends on a crate in `apps/` or `extensions/` (D3).

## 3. Dependency direction (enforced by `cargo xtask layering`)

```text
oino-ai ◄── oino-session ◄── oino-protocol ◄── oino-extension-api
   ▲             ▲                 ▲                  ▲
   ├── oino-agent ◄── oino-tools   │                  │
   │                               │                  │
oino-settings ◄── oino-resources   │                  │
oino-settings ◄── oino-models      │                  │
                                   │                  │
      oino-core ──────────────────►(all of the above)◄── oino-wasm-host
          ▲
      oino-client ◄── oino-rpc (client half uses only oino-protocol)
          ▲
   {oino-tui, oino-acp, apps/oino-ui} ◄── {crates/oino, apps/oino-desktop, apps/oino-mobile}
   oino-view ◄── {oino-tui, apps/oino-ui}
extensions: oino-ai, oino-protocol ◄── oino-extension ◄── {oino-provider-kit, unipi-kit} ◄── components
```

Forbidden edges (layering test fails the build):

1. Anything below `oino-client` depending on ratatui, crossterm, gpui*, wasmtime*,
   agent-client-protocol, clap.
2. `oino-core` depending on `oino-wasm-host` (it only knows `oino-extension-api`).
3. `oino-ai`, `oino-protocol`, `oino-extension` (guest) depending on tokio, reqwest, or any
   crate that does not build for `wasm32-wasip2`. CI builds `oino-ai` and `oino-protocol` for
   `wasm32-wasip2`.
4. `oino-session` depending on async runtimes.
5. `oino-tui` / `apps/*` reaching into `oino-core` internals: they use `oino-client` only
   (the in-process backend is constructed by the binary/app shell and passed in as
   `Arc<dyn SessionBackend>`).

## 4. Process model

### 4.1 One runtime, several projections

```text
                       ┌──────────────────────── oino-core ───────────────────────┐
                       │ AgentSessionRuntime (per session) ── AgentSession         │
 Services (per cwd) ──►│   agent loop · tools · compaction · retry · queues        │
 settings, resources,  │   ExtensionRunner ── HostServices impl ──► ExtensionRuntime│──► oino-wasm-host
 models/auth, packages │   events: AgentSessionEvent + UiRequest stream            │    (wasmtime, components)
                       └──────────────▲────────────────────────────▲──────────────┘
                                      │ typed Rust API              │
                              oino-client::InProcessBackend         │
             ┌────────────────┬───────┴────────┬──────────────┐     │
          oino-tui      apps/oino-desktop   oino-rpc server  oino-acp adapter
        (interactive)     (GPUI)         (--mode rpc, serve)   (--mode acp)
                                              ▲
                                  oino-client::RpcBackend (remote TUI, mobile, child tools)
```

- A **session** = one `AgentSessionRuntime` wrapping one `AgentSession` bound to one session
  file (or in-memory). Runtime operations (`new`, `switch`, `fork`, `clone`, `import`) replace the
  inner `AgentSession` and rebind subscribers (runtime §4).
- **Services** are per `(cwd, agent_dir)`: `SettingsManager`, `ResourceLoader`, `ModelRegistry`
  (with `AuthStorage`), `PackageManager`, `ExtensionRunner` (loaded components shared by all
  sessions of that cwd in this process; per-session state is keyed by session id inside the
  runner).
- **Threads**: `oino-core` runs on a tokio multi-thread runtime owned by the embedding process
  (binary: `#[tokio::main(flavor = "multi_thread", worker_threads = 4)]`; desktop: a dedicated
  runtime started at app launch, see gpui-app §3). Wasmtime uses async support with epoch
  interruption; each component instance lives in its own `Store` driven on the runtime.
- **Nested agents** (subagents, btw, sidekick…) are additional `AgentSession`s created by the
  runner through `HostServices::agents_spawn`, sharing Services and the provider components
  (D8). They do not get their own `ExtensionRunner` unless `extensions: inherit` is requested
  (runtime §12).

### 4.2 Event and command flow

- Clients send **commands** (`oino_protocol::rpc::RpcCommand` enum — the same enum the RPC
  codec parses) and receive a single ordered stream of `oino_protocol::events::ClientEvent`:
  `AgentSessionEvent` | `ExtensionUiRequest` | `ExtensionError` | Oino additions
  (modes §3.3). `InProcessBackend` passes the enums over channels without serialisation;
  `RpcBackend` serialises them. The UI cannot tell the difference, which makes RPC parity
  testable through every client test (D4).
- `oino-client` contract (owner modes):

```rust
pub trait SessionBackend: Send + Sync {
    /// Any pi or `_oino/*` command (oino_protocol::rpc::RpcCommand); returns the typed `data`.
    fn send(&self, cmd: RpcCommand) -> BoxFuture<'_, Result<RpcResponseData, ClientError>>;
    /// Ordered event stream for this session (new subscription each call).
    fn events(&self) -> BoxStream<'static, ClientEvent>;
    /// Answer a dialog (`extension_ui_response`); idempotent, first answer wins.
    fn ui_respond(&self, response: UiResponse);
    fn session_id(&self) -> String;
}
pub trait SessionHubBackend: Send + Sync {          // implemented in-process and over `serve`
    fn open(&self, req: OpenSession) -> BoxFuture<'_, Result<Arc<dyn SessionBackend>, ClientError>>;
    fn attach(&self, session_id: &str) -> BoxFuture<'_, Result<Arc<dyn SessionBackend>, ClientError>>;
    fn list(&self) -> BoxFuture<'_, Result<Vec<HubSession>, ClientError>>;
    fn close(&self, session_id: &str) -> BoxFuture<'_, Result<(), ClientError>>;
}
```

  `oino_client::fake::FakeBackend` (scripted events, recorded commands) lets tui-client and
  gpui-desktop start before core lands.
- Backpressure: per-subscriber bounded channel (capacity 1024 events). When full, the core
  never blocks the agent loop; it **coalesces** consecutive `message_update` and
  `tool_execution_update` events of the same id (keeping the latest cumulative state and
  concatenated deltas) and drops `bash_execution_update` deltas into a single concatenated
  delta. Other events are never dropped; if a subscriber still cannot keep up after coalescing
  for 5 s it is disconnected with `ClientEvent::Lagged`.

### 4.3 Embedding modes

| Host | Backend | Notes |
|---|---|---|
| `oino` (interactive) | `InProcessBackend` | default; `--remote <url>` switches to `RpcBackend` |
| `oino -p` / `--mode json` | direct `AgentSession` (no client crate needed) | modes §2 |
| `oino --mode rpc` | `RpcServer` over `InProcessBackend` | stdio, single session (pi-compatible) |
| `oino serve` | `RpcServer` over `SessionHub` (multi-session `InProcessBackend`s) | TCP+TLS, many clients, modes §5 |
| `oino --mode acp` | `oino-acp` over `InProcessBackend` | modes §6 |
| Oino Desktop | `SessionHub` in-process; optional embedded `serve` listener | gpui-app §3 |
| Oino Mobile | `RpcBackend` over TCP+TLS to a desktop/server | D16 |

## 5. Filesystem layout

Agent dir `~/.oino/` (override `OINO_AGENT_DIR`), laid out like pi's `~/.pi/agent/`:

```text
~/.oino/
  settings.json  keybindings.json  models.json  auth.json  trust.json  secrets.json
  SYSTEM.md  APPEND_SYSTEM.md  AGENTS.md          # optional, user-authored only (never auto-created)
  extensions/<id>/                                # installed packages (extension-api §7)
  skills/  prompts/  themes/
  sessions/--<cwd>--/<ts>_<sessionId>.jsonl       # session-v3 §6.1
  sessions/.legacy/                               # migrated pre-v1 files (D21)
  state/<ext-id>/{global,workspace/<wsid>,session/<sid>}/   # D10
  bundled/<id>@<version>-<hash8>/                 # extracted bundled resources (D14)
  cache/  (wasm compile cache: cache/wasmtime/, model catalogs: cache/models/)
  logs/oino.log  logs/ext/<ext-id>.log
  tmp/                                            # bash full-output files, bg task output
```

Project dir `.oino/` at **cwd** (not git root): `settings.json`, `SYSTEM.md`,
`APPEND_SYSTEM.md`, `extensions/`, `skills/`, `prompts/`, `themes/` — all trust-gated
(runtime §9.7). Oino never creates project files implicitly. `.agents/skills` (cwd up to repo
root) and `~/.agents/skills` are discovered like pi.

## 6. Error and logging model

- Libraries: one `thiserror` enum per module boundary (`SessionError`, `ToolError`,
  `ExtensionError`, …), `#[non_exhaustive]`. No `anyhow` outside `crates/oino`, `xtask`, apps.
- Logging: `tracing` everywhere; the binary installs a subscriber writing to
  `~/.oino/logs/oino.log` (rotating 10 MiB × 3) and stderr only with `--verbose`. Stdout is
  reserved for mode output (print/json/rpc/acp).
- Extension diagnostics: `ExtensionError{extensionPath, event, error, stack?}` are emitted as
  `extension_error` client events (pi RPC shape) and logged to `logs/ext/<id>.log`.

## 7. Concurrency rules inside `oino-core`

- `AgentSession` state is behind one `tokio::sync::Mutex<SessionState>`; it is never held across
  an `.await` on provider/tool/extension calls. Long operations take a snapshot, run, then
  re-lock to commit.
- Session writes happen only from the session task (single writer) in event order: an entry is
  appended before the corresponding event is published.
- Extension dispatch for one event runs handlers **sequentially in load order** (pi parity);
  different events may be dispatched concurrently only when pi does so (tool execution in
  parallel mode). Notification events emitted by the loop are awaited in order (pi
  `subscribe` semantics).

## 8. Legacy freeze procedure (integration, P1 first commit)

1. `git mv crates/* legacy/crates/`, `git mv extensions/crates legacy/extensions/crates`,
   `git mv extensions/built-in legacy/extensions/built-in`, `git mv wit/extension.wit
   legacy/wit/extension.wit`, `git mv scripts/build-wasm-extensions.sh legacy/scripts/`.
2. Write new root `Cargo.toml` (globs, edition 2024, workspace lints from quality §2),
   `extensions/Cargo.toml`, `apps/` is created by gpui-desktop in P3.
3. Add `legacy/README.md`: "frozen, not built, deleted in P5; read with your editor or
   `git show`". Add `legacy/` to `exclude` of every workspace.
4. Remove committed `.wasm` binaries from the tree except under `legacy/`.
