# Deviations: gpui-mobile

| § (gpui-app.md unless noted) | Change | Reason | Impact |
|---|---|---|---|
| §2, §4 (D16) | **Embedded core, not remote-only.** `oino-mobile` links `oino-core`, `oino-wasm-host` (wasmtime + Cranelift), `oino-client` (`in-process`) and `oino-bundle`, and runs every bundled component on the phone through the desktop's `EmbeddedHost`. No `RpcBackend`, pairing, QR scan or Keystore/Keychain tokens yet. | Work instruction: "embedding oino-core + bundled extensions". Verified on Android 15 (arm64): Cranelift compiles and runs the components on device. | Remote attach (§4 bullets 1–2, §8 "pair with desktop serve") still to do once `oino serve` + `RpcBackend` exist; the `oino://` deep-link filter is already declared on both platforms. |
| §4 | **iOS cannot JIT**: the same build links on iOS, but Cranelift code cannot be made executable on a device, so extension components (providers included) fail to load. | wasmtime needs Pulley (`Config::target("pulley64")`, `pulley` feature) for no-JIT platforms; `oino-wasm-host` has no hook to select it. | Request to wit/host owner (see report). Until then iOS = core + built-in tools without providers, or remote once RpcBackend lands. |
| §2 | `EmbeddedHost` (`oino-desktop/src/embedded.rs`) and `DemoHost` (`demo.rs`) are compiled into `oino-mobile` **by source** (`#[path]`), with a mobile `prefs` module (`<agent>/mobile.json`). | Both live in the desktop binary crate; moving them into a shared crate is gpui-desktop's file set. | Request: move them into `oino-ui` behind an `embedded` feature (or an `oino-host` crate) and drop the `#[path]` includes. |
| §2 | `gpui-mobile` vendored from **longbridge/gpui-mobile `c24a130`** (already on gpui-pre =0.3.9), not itsbalamurali `main` (still gpui-pre =0.3.6). Patches listed in `apps/vendor/gpui-mobile/VENDOR.md`: no `offscreen`, rlib only, own `[workspace]` + `rustfmt.toml` (kept out of the root workspace and `cargo fmt --all`), iOS `set_app_configure` (asset source), Android `nativeInsets` (system-bar + IME insets from the activity). | Single gpui-pre version (`cargo tree -d -i gpui-pre` empty). | Re-apply patches on update. |
| §4 | **iOS host is a full-screen GPUI window** (`main.m` + `CADisplayLink`), not a UIKit navigation bar + native input bar around an embedded GPUI view. GPUI renders everything on both platforms, including the composer (soft keyboard via gpui-mobile). | One layout (`oino_ui::mobile::MobileShell`) for both platforms; the native-chrome variant needs Swift glue that cannot be built or tested from the Linux host. | Revisit after the first device run on `desmondgiam`. |
| §4 | Screens: sessions (grouped, live dots, filter, new), conversation (desktop `SessionPane` + app bar: back, title, model·thinking, stop, actions), bottom sheets (model + thinking, actions incl. `/login`, compact, `sidePane` panels), full-screen side sheet (diff / output / panels), settings (theme, thinking, tool rows, extensions, about). Dialogs and overlay panels are the desktop modals, capped to the window width. Not done: extension settings hub (needs schema commands), notifications as OS notifications (toasts only), file attachments. | Same command gaps as gpui-desktop. | needs modes. |
| §4 | Android host is `GpuiActivity ⊂ GpuiInputActivity` (NativeActivity) from gpui-mobile's example, trimmed to the enabled packages; `targetSdk 36` (edge-to-edge enforced, hence the insets patch). | — | — |
| — | Shared views touched: `views/dialog.rs` (`max_w(relative(0.94))`) and `views/session_pane.rs` overlay panel (`max_w(relative(0.96))`) so dialogs and panels fit a phone; no desktop-visible change. `oino-ui` gains feature `mobile` and `src/mobile/`. | Dialogs (`/login`, approvals) were clipped on a 360 dp screen. | gpui-desktop owns those files; flagged in the report. |
