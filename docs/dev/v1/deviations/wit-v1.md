# Deviations: wit-v1

Owner: `wit-v1`. Format per README §5: section, change, reason, impact.

## Contract differences

| # | Section | Change | Reason | Impact |
|---|---|---|---|---|
| 1 | extension-api §3 (WIT) | Identifiers that are WIT keywords are escaped: `%list` (agents, tasks, services), `%flags` (registration, init-input), `%from` (`session.branch`). | WIT keywords. | Generated names are unchanged (`list`, `flags`, `from`). |
| 2 | extension-api §3 `host-info` | Record `workspace` renamed `workspace-info` (function `workspace` unchanged). | Duplicate name in one interface is invalid WIT. | Guests use `WorkspaceInfo`. |
| 3 | architecture §1, extension-api §2 | WASI deps live in `wit/oino-extension/deps/` and are **0.2.12** (spec: `wit/deps/`, 0.2.3). | `wasm-tools`, `wit-bindgen` and `wasmtime::bindgen!` resolve deps relative to the package dir; 0.2.12 matches wasmtime-wasi 48's own WIT so the host maps `wasi:*` to `wasmtime_wasi::p2::bindings`. | None for guests (Rust std's wasip2 imports are semver-compatible). |
| 4 | extension-api §5.7 | `ext-workspace` and `ext-session` preopens are the *roots* `state/<id>/workspace/` and `state/<id>/session/`; guests use `/ext-workspace/<wsid>/…` and `/ext-session/<sid>/…` (SDK `fs::ext_workspace()`, `fs::ext_session(sid)`). | One instance serves every session of the process (principle 5); WASI preopens are fixed per store. `kv` scopes resolve the per-session/workspace directory from the call context. | unipi ports use the SDK helpers. |
| 5 | extension-api §5.7 | `fs.agentDir: read` preopens `agent/{sessions,skills,prompts,themes,extensions,bundled}` (those that exist), not the whole agent dir. | WASI cannot mask single files; this guarantees `auth.json`/`secrets.json` stay unreachable. Settings/models/trust are available through `control`. | unipi that read `trust.json`/`models.json` directly must use host APIs. |
| 6 | extension-api §5.6 | `impersonate` is accepted (permission-checked) but served by reqwest without fingerprinting; responses report `impersonated: false`. No `wreq`/`fingerprint` feature yet. | `wreq` pulls BoringSSL; deferred until web-api needs it. | unipi web-api smart-fetch falls back to plain TLS. |
| 7 | extension-api §5.1 | No pooling allocator; fuel unused; deadlines = per-call tokio timeouts (`limits.hookTimeoutMs`, `toolCallHookTimeoutMs` for `tool_call`) plus epoch-based async yielding every 10 ms. A timed-out handler's guest task keeps running until it yields; the caller gets an error. | wasmtime concurrent calls cannot be interrupted individually without trapping the instance. | Runaway guest loops still yield (other calls progress); a stuck extension is visible as timeouts. |
| 8 | extension-api §5.2 | Bus, services, secrets, background tasks and delivery of host-produced `oino_*` events (timers, tasks, bus) are served by `oino_wasm_host::LocalServices` (wrapping the `HostServices` given to `load`), not by core. `WasmRuntimeOptions::local_services = false` hands them to `HostServices`. | core-runtime deferred these (its deviations "Deferred"). | When core implements them, switch the option off. |
| 9 | extension-api §6 | `HostServices` methods have default bodies returning `HostError::Failed("<capability> is not supported by this host")`. `LoadedPackage` gained `bundled: bool` (grants such as `"*"` hosts/programs are honoured only for bundled packages, §5.6/§7.3). | Additive coverage; bundled trust needs to be explicit. | Core implements methods incrementally. |
| 10 | extension-api §6 | `oino-extension-api` does not depend on `oino-protocol` (not created yet); all pi data is `RawJson`. | Contract crate absent. | None. |
| 11 | architecture §3 | `oino-wasm-host` has an optional (default) `core` feature depending on `oino-core` for `core_bridge` (adapters to `oino_core::extensions::{api,host}` and `services::ExtensionLoader`). | core-runtime deviation 11: core still has its own contract copy. | Remove the feature once core re-exports `oino-extension-api`; core never depends on the wasm host. |
| 12 | extension-api §5 / charter | `oino-wasm-host` uses `#![deny(unsafe_code)]` (not `forbid`) with `#[allow(unsafe_code)]` only on the `bindgen!`-generated module (`TypedFunc::new_unchecked` in export accessors). The guest SDK does the same for `wit_bindgen::generate!`. | Generated code; `forbid` cannot be overridden. | None. |
| 13 | extension-api §9 | `testing::MockHost` (native SDK tests) is not implemented; extensions are tested as components through `oino_wasm_host::testing::Harness` against `RecordingHostServices`. | Time; the harness covers the same ground with the real ABI. | unipi crates write integration tests in `crates/oino-wasm-host`-style harnesses or request MockHost. |
| 14 | extension-api §9.1 | SDK handlers receive `&'static Self` (the extension value is leaked once per instance); `Extension::init(&'static self, cx: &mut Init<Self>)`. Typed event payload structs are not provided yet (`Event::decode::<T>()` with caller types; `oino-protocol::ext` pending). | Simplest sound shape for `'static` handler futures on a single-threaded executor. | Examples in the SDK README. |
| 15 | extension-api §8 | `cargo xtask wasm` builds each component in its own cargo invocation (feature unification), copies declared resources, and writes `checksums.json` (sha256 per file + rustc/wasm-tools versions). `oino-bundle` gained feature `fixtures`; the `oino.docs` pseudo-package and `BundledSource` (oino-core) are not implemented here. | Docs bundling belongs with integration/docs; `BundledSource` lives in core. | integration: add `oino.docs`; core: consume `oino_bundle::BUNDLED` via `oino_wasm_host::packages::from_bytes`. |
| 16 | extensions/Cargo.toml | Members are `["*/*"]` with `exclude = ["additional", "built-in", "dist", "target"]` (spec: four explicit globs). | Cargo rejects globs that match nothing (`providers/*`, `unipi/*` are empty today). | New component dirs are picked up automatically. |
| 17 | extension-api §5.4 | Process stats/trees are implemented for Linux (`/proc`); macOS/Windows return `unsupported` (no `libproc`/`sysinfo` yet). Windows signals map to kill. | Scope. | watchdog on macOS/Windows needs follow-up. |
| 18 | extension-api §4.1 | `oino_process` events are not emitted (no `subscribe` flag on spawn); `tasks.adopt-bash` forwards to `HostServices::tasks` (core bash detach). | Spec gives no subscribe field; adopt needs core's bash registry. | background-tasks uses `child.wait()` / `bash-detach`. |
