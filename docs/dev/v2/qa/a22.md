## What changed

- **Seam**: `lib/board/transport.ts` → `hostClient(hostId).request('board_cli',
  {args, project?})`, one CLI process per call (`--json`, actor `user`,
  subcommand allow-list, ext-abi §5.5 outcome). Live updates:
  `board_watch{on}` + `board_changed` hub events on the single `events_open`
  stream (`lib/board/live.ts`), debounced 250 ms, reconnect with backoff.
- **Derived data** (the daemon is gone): `rules` is the client mirror of the
  transition table (`USER_RULES`); `projects`/`running`/`dashboard` are derived
  from `project list` + per-project `list --all`; `doneLane`/`archiveLane`
  compose per-task `move`s (no bulk subcommands exist).
- **Attachments**: bytes go through the host (`blob_put_bytes` → `fs_import`
  into `~/.oino/uploads`), then the CLI's `attach`; downloads read by board
  path through `blob_get_bytes`.
- **Removed** (no CLI surface): `lib/board/summarize.ts`, `SummarizeSheet`,
  `BoardSettingsSheet`, `vite.config.board-capture.ts`, the `/api/*` transport
  and its `webTransport.test.ts`. `PcChip` stays on the Board.
- **Final-lane moves** confirm before writing (the CLI has no undo token), so
  drag-and-drop into Done/Cancelled opens the confirm sheet; the `after` order
  is applied once the move lands.
- **Mock**: `src/dev/mock/board.ts` answers `board_cli` argv like the real CLI
  (payloads cloned, like stdout) and emits `board_changed` on writes; the mock
  host wires `board_cli`/`board_watch`; scenarios `board-lanes`,
  `board-dashboard` (desktop + phone).

## Defaults taken

- `board_cli` answers a **domain outcome** (`{ok:false,error,kind}`) rather than
  an `invoke` rejection, so rule refusals surface as messages, not crashes.
- Attachments are staged under `~/.oino/uploads` on the PC (board file paths are
  board-relative; `status.home` resolves them).
- The Board treats `board_changed{project}` for another project as a counts
  refresh only (task list reload is scoped to the open project).
