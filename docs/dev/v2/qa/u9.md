Findings / follow-ups:

- **First render & patch rows read high because they were measured in dev
  mode.** A production-build re-measure (and the Pixel-class device run) is
  the A29/A30 gate; re-run `?page=perf` against a prod build there.
- **Solver**: cold kiwi solves (any Min/Max/Ratio, exotic flex) cost ~1.2 ms
  for 16 children — the §13.5 0.2 ms row is met by the new closed-form path
  (flex=Start, {Length,Percentage,Fill}, fits; exactness proven by the vector
  corpus) and by the LRU memo for repeats. Residual: panels that solve
  Min/Max-heavy specs on every resize frame; if the device run flags it,
  extend the fast path or reuse a warm kiwi solver.
- Memory row needs `--js-flags=--expose-gc` for a real reading.
