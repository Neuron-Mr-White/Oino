# Provider components (`providers-v1`)

WASM components (world `provider-extension`) that implement the pi-ai 1.4.0 wire APIs on
`oino-ai` types. Core has no provider code: it dispatches each model by its `api` to the
component whose manifest lists that api in `provides.apis`.

| Component | Dir | `provides.apis` | Providers registered |
|---|---|---|---|
| `oino.openai-compat` | `openai-compat/` | `openai-completions` | OpenRouter, Groq, DeepSeek, Together, Fireworks, Cerebras, Hugging Face, NVIDIA, Moonshot, Kimi, Qwen, Xiaomi, z.ai, OpenCode, Baseten, Ant Ling, Vercel AI Gateway, GitHub Copilot (device-code OAuth), Cloudflare AI Gateway, Cloudflare Workers AI, Ollama, LM Studio, Mistral, DeepInfra, Chutes, Perplexity |
| `oino.openai-responses` | `openai-responses/` | `openai-responses` | OpenAI (API key or Sign in with ChatGPT OAuth), xAI, Meta |
| `oino.anthropic` | `anthropic/` | `anthropic-messages` | Anthropic (API key or Claude Pro/Max OAuth), MiniMax |
| `oino.openai-codex` | `openai-codex/` | `openai-codex-responses` | OpenAI Codex (ChatGPT Plus/Pro OAuth: browser or device code) |
| `oino.azure` | `azure/` | `azure-openai-responses` | Azure OpenAI (`AZURE_OPENAI_*`; its chat-completions models stream through `oino.openai-compat`) |
| `oino.google` | `google/` | `google-generative-ai`, `google-vertex` | Google (Gemini API key), Google Vertex AI (API key or Application Default Credentials) |
| `oino.bedrock` | `bedrock/` | `bedrock-converse-stream` | Amazon Bedrock (bearer token or IAM credentials with SigV4; env or static `~/.aws` profiles) |
| `oino.router` | `router/` | `oino-router` | `oino` (Oino Router: Claude models on Anthropic Messages, the rest on chat completions) |

Providers whose models use several APIs (GitHub Copilot, Cloudflare AI Gateway, OpenRouter, Azure)
are registered by one component and streamed by whichever component implements each model's `api`;
the per-provider differences pi applies in its provider layer (Copilot `X-Initiator` /
`Openai-Intent` / `Copilot-Vision-Request` headers and token `proxy-ep` endpoint, Cloudflare
`{CLOUDFLARE_ACCOUNT_ID}`/`{CLOUDFLARE_GATEWAY_ID}` endpoints and `cf-aig-authorization`, Azure
endpoint + deployment name) live in `oino_provider_kit::providers` and apply in every wire.

## OAuth (`oauth-login` / `oauth-refresh`)

A provider's OAuth calls go to the component that registered it (registration `"oauth": true`);
every registration's `api` is one its own component provides, so routing by registration `api`
(as core already does for `list-models`) reaches the same component. The flows drive `ui.select` / `ui.input` / `ui.notify` / `ui.open-url` and the
loopback listener, and return pi's credential JSON:

| Provider | Component | Flow (pi source) | Credential |
|---|---|---|---|
| `anthropic` | `oino.anthropic` | PKCE browser or copy-code (`auth/oauth/anthropic.js`) | `{type, access, refresh, expires}` |
| `github-copilot` | `oino.openai-compat` | GitHub device code, Copilot token, model policies (`auth/oauth/github-copilot.js`) | `+ enterpriseUrl?, availableModelIds` (filters `list-models` when passed back) |
| `openai-codex` | `oino.openai-codex` | PKCE browser on `localhost:1455` or device code (`auth/oauth/openai-codex.js`) | `+ accountId` |
| `openai` | `oino.openai-responses` | Sign in with ChatGPT, dynamic client (`auth/oauth/openai-chatgpt.js`) | `+ clientId, scopes` |

The access token is what core passes as `apiKey` (Copilot tokens carry their API host).

## Ambient credentials

Bedrock (AWS env keys / profiles) and Vertex (ADC) authenticate without an API key. Their
registrations list the variables whose presence means "configured" (`AWS_PROFILE`,
`AWS_ACCESS_KEY_ID`, `GOOGLE_CLOUD_PROJECT`, …) so core's auth check passes; a key equal to one of
those marker values is ignored by the component. Profiles are read from `~/.aws` (`fs.paths` alias
`aws`), ADC from `~/.config/gcloud` (alias `gcloud`).

Wire logic lives in `extensions/sdk/oino-provider-kit` (pure, natively tested against pi-ai
oracle fixtures); each component is a thin `Provider` impl over `oino_provider_kit::guest`.

- Catalogs: `*/catalog.json`, generated by `node scripts/pi-oracle/providers-v1/catalog.mjs`.
- Goldens: `node scripts/pi-oracle/providers-v1/payload.mjs` and
  `node scripts/pi-oracle/providers-more/payload.mjs` → `extensions/sdk/oino-provider-kit/tests/fixtures/<api>/`;
  `cargo test -p oino-provider-kit` (in `extensions/`) replays them (165 fixtures, 8 APIs; Bedrock
  SigV4 signatures are recomputed from pi's signed headers).
- Host end to end: `scripts/pi-oracle/providers-{v1,more}/host-e2e.rs` (copy into
  `crates/oino-wasm-host/tests/`).
- Build/bundle: `cargo xtask wasm` → `extensions/dist/oino.*` → `crates/oino-bundle` (feature `providers`).
- Deviations from the specs: `docs/dev/v1/deviations/providers-v1.md`; providers-more additions below.

## Deviations (providers-more)

| # | pi behaviour | Oino | Reason |
|---|---|---|---|
| M1 | Codex `transport: "auto"` tries a WebSocket (`responses_websockets`) and falls back to SSE | SSE only (`transport` ignored) | WIT `http` has no WebSocket; pi itself falls back to SSE when WebSockets fail |
| M2 | Codex SSE bodies are zstd-compressed (`content-encoding: zstd`) | uncompressed JSON | pi sends uncompressed JSON where `zstdCompressSync` is unavailable; no zstd encoder in the component |
| M3 | Codex retries with its own `isRetryableError` / `BASE_DELAY_MS` policy | the shared provider retry policy (`maxRetries`, default 0) | one retry loop in the kit |
| M4 | Bedrock credential chain (SSO, `credential_process`, assume-role, ECS/IMDS, web identity) | env keys, bearer tokens, static `~/.aws` profiles | no process/IMDS access from the component; markers still satisfy core's auth check |
| M5 | Bedrock SigV4 signs the SDK's headers (`:authority`, `amz-sdk-*`, `x-amz-user-agent`) | signs `host`, `content-type`, `x-amz-date`, `x-amz-content-sha256`, `x-amz-security-token` | no AWS SDK; the golden recomputes pi's signature with Oino's signer |
| M6 | Vertex ADC via `google-auth-library` (any credential type, any file path) | `authorized_user` and `service_account` ADC files under `~/.config/gcloud` | WASM sandbox preopens; external-account / impersonated credentials unsupported |
| M7 | pi provider auth `env` (stored credential env: Cloudflare account/gateway, Azure, AWS, GCP) is passed as `options.env` | `options.env` is honoured; otherwise the component's granted host env (`permissions.env`) | core does not store credential env yet |
| M8 | Bedrock non-JSON error bodies surface V8's `JSON.parse` message | the same text shape, generated (`Unexpected token …`) | no V8 |
| M9 | Google tool-call ids without a provided id use a module-global counter | per-request counter | no shared module state across requests |
| M10 | Cloudflare without `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_GATEWAY_ID` is "not configured" in pi's auth layer | lone error naming the missing variable | core only checks `CLOUDFLARE_API_KEY` |
